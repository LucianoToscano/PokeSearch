9. **REGRA CRÍTICA E RECORRENTE — "Library file not found" NO CHATGPT (27/10/2026):** esse erro surge ao clicar em links de anexos gerados/sandbox na interface do ChatGPT; NÃO classificá-lo como falha Android/Gradle, APK inválido ou problema de assinatura sem evidência. **PROIBIDO entregar um APK apenas por `sandbox:/mnt/data/...` ou declarar "download funcionando" somente porque o arquivo existe no container.** Para toda LT:
   - GitHub Actions `upload-artifact` concluído = canal de entrega QA primário, incluir URL exata e verificada da execução/artefato (e indicar que pode exigir conta GitHub e expira). Para distribuição persistente, preparar release **apenas mediante autorização explícita**, e validar URL direta do asset, nunca inventá-la. Manter o APK anterior.
   - Antes de anunciar a entrega, conferir nome exato, bytes, SHA-256 do APK e ZIP, integridade do ZIP, versionName/versionCode, SHA-256 do certificado de assinatura e `SOURCE_COMMIT`.    - Link interno do ChatGPT é **secundário/opcional**: conferir existência do caminho no runtime atual, mas não assegurar que o aplicativo do usuário abrirá o anexo; falha dessa interface não é corrigível pela compilação. Se a plataforma falhar, oferecer imediatamente o link GitHub do artefato já verificado, sem recompilar, sem recriar arquivos e sem deixar o usuário preso num loop de sandbox.
   - Em respostas futuras, verificar primeiro esta regra e `docs/PROTOCOLO_ENTREGA_APK_SEM_LIBRARY_NOT_FOUND.md`; registrar cada reincidência como falha de distribuição/UX.
